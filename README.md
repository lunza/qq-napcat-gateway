# QQ 机器人（NapCat + 自研 gateway）— 由 harness 托管

> 2026-11-12 落地。协议端 **NapCat 4.18.42**，业务层由 **harness** 接管，中间是自研薄层 `qq-gateway`。

## 一、选了哪个框架，为什么

| 候选 | 能否复用"已登录账号" | 结论 |
|---|---|---|
| **NapCatQQ**（12.6k★，日更） | 能，注入本机 QQ 并快速登录同一账号 | **采用**。macOS 官方有安装器与文档，OneBot11 生态最全 |
| LuckyLilliaBot | 能（独立协议实现） | 备选。macOS 只发了 arm64 包，本机 Intel 需用 Docker |
| Lagrange.Core | 能（独立协议，需签名服务） | 不选。Release 停在 2025-08 nightly，脱离官方客户端风控更敏感 |
| NoneBot2 / AstrBot | 本身不登录 QQ，必须另配协议端 | 不选。它们自带"第二套大脑"和 WebUI，和 harness 建档管理重复 |

**结论：有现成好用的框架（NapCat），不需要自研框架；但"由 harness 管理"这一层没有任何框架提供，必须自研，这就是 `qq-gateway`。**

## 二、架构

```
QQ 7.0.3 (Electron, 镜像实例) ──注入──> NapCat 4.18.42
                                          ├─ OneBot11 HTTP 127.0.0.1:3000  (发消息)
                                          └─ OneBot11 WS   127.0.0.1:3001  (收事件)
                                                     │
                                          qq-gateway (node, 本仓库)
                                          路由/去重/限流/@判定/防回环
                                                     │
                                          dsh-bridge.sh → dsh --profile headless-qq
                                          (harness 推理后端, --session-id 延续对话)
```

## 八、主管账号与命令系统（2026-11-12）

主管账号（`config/qq.json` → `admin.owners`）：**`admin.owners` 里配置的 QQ 号**（默认占位 `1000000002`，首次部署请改成你自己的号）。

主管在**私聊**或**群里 @机器人** 后发送 `/命令` 即可操作。命令不会进入模型、不污染对话上下文。

| 命令 | 说明 |
|---|---|
| `/help` | 显示可用命令（主管看到全部，其他人只看到 `/help` `/whoami`） |
| `/status` | 在线状态、运行时长、回复模式、在线率、掉线次数 |
| `/mode <harness\|echo\|off>` | 切换回复模式：模型对话 / 回显 / 只记录不回复 |
| `/new` | 清空当前会话上下文 |
| `/log [n]` | 查看最近 n 条收发记录（默认 10，最多 50） |
| `/report` | 在线率与最近掉线明细 |
| `/whoami` | 显示自己的 QQ 号与是否主管 |
| `/silence <分钟>` | 静默 N 分钟（`0` 取消）；静默期间只有主管本人的命令可用 |
| `/owner add\|remove\|list <QQ号>` | 管理主管账号（仅主管） |
| `/allow add\|remove\|list <private:QQ\|group:群号>` | 管理对话白名单（仅主管） |

**权限模型**：
- 非主管发 `/help` → 只看到 2 条公开命令，不暴露运维命令。
- 非主管发 `/status` `/mode` 等 → 回复"需要主管权限"。
- 非主管发未知命令 → 当作普通聊天，不提示。
- 命令配置改动（`/mode` `/owner` `/allow` `/silence`）立即写回 `config/qq.json` 并运行时生效。

新增命令：在 `gateway/src/commands.ts` 的 `COMMANDS` 表里加一项即可；测试在 `tests/commands.ts`。

## 十、技能系统（# 触发）

### 触发规则（2026-11-12 修订）

| 你发送 | 结果 |
|---|---|
| `#help` 或 `#帮助` | 列出所有可用技能 |
| `#今日运势` | 触发「今日运势」技能 |
| `帮我 #今日运势` | 同样触发（句中包含即可） |
| `今日运势`（不带 #） | **不触发**，当普通聊天处理 |

- 全角 `＃` 也识别（中文输入法下很常见）
- `#HELP` 大小写均可
- 技能名本身也能当触发词（`#今日美图` 等价于 `#来张图`）
- 多个 # 同时出现时，取**触发词最长**的那个

### `#help` 输出示例

```
【可用技能】
#今日运势  —  今日运势
    其他写法：#运势、#算一卦

发送 #技能名 即可触发，例如 #今日运势
```

### 配置（`config/qq.json` 的 `skills` 段）

```json
{
  "skills": {
    "enabled": true,
    "items": [
      {
        "id": "fortune",
        "name": "今日运势",
        "triggers": ["今日运势", "运势", "算一卦"],
        "prompt": "你在帮对方测今日运势……（写清楚要它做什么、输出成什么样）",
        "enabled": true,
        "cooldownSec": 60
      }
    ]
  }
}
```

> `triggers` 里**不写 #**，匹配时自动要求消息里有 `#触发词`。

| 字段 | 说明 |
|---|---|
| `triggers` | 触发词，需在消息里以 `#触发词` 形式出现 |
| `prompt` | 命中后注入给模型的指令 |
| `cooldownSec` | 同一会话内冷却秒数，`0` 表示不限制 |
| `enabled` | 单个技能开关；顶层 `skills.enabled` 是总开关 |

### 两种管理方式
1. **设置页**：设置 → QQ 机器人 → 「技能」区块
2. **Agent 工具**：`qq_skills`（list / add / remove / toggle）

### 生效时机
gateway 每轮回复都重新读取配置，**改完立即生效，无需重启**。

### 验证结果
- 技能引擎单测 **30/30 通过**（# 触发、全角、#help、冷却、长词优先、开关、注入）
- 端到端测试 **通过**：`#help` 经真实 gateway 返回技能列表；普通消息不误触发

## 十一、取图技能（e621 热门）

### 用法

QQ 里发 **`#来点色图`**（或 `#色图`、`#来张色图`），机器人会：
1. 用无头 Chrome 打开 `https://e621.net/popular?date=<当前时间>&scale=day`
2. 从页面的 article 里收集**所有帖子**，按 `data-file-ext` 过滤出**静态图与 GIF**
3. 随机挑一个，进详情页取**原图**地址（`/data/download/...` 直链，不是 sample 压缩版）
4. 通过 OneBot 图片消息段发送

### 关键约束

| 约束 | 实现 |
|---|---|
| **只发静态图与 GIF** | 允许 `jpg/jpeg/png/gif/webp` |
| **绝不发视频** | 排除 `webm/mp4/mov/avi/mkv/swf/flv`；列表页和详情页各校验一次 |
| 走页面元素，不走 API | 该站对非浏览器请求直接重置连接，只有真实浏览器能拿到页面 |
| 读原图 | 优先 `/data/download/`，其次 `/data/` 原始路径，最后才退回 `img#image`（并替换 sample 路径） |

### 配置（`config/qq.json`）

```json
{
  "id": "e621",
  "name": "来点色图",
  "triggers": ["来点色图", "色图", "来张色图"],
  "type": "e621",
  "e621": { "scale": "day" },
  "enabled": true,
  "cooldownSec": 0
}
```

- `type`：`prompt`（默认，注入提示词）或 `e621`（直接抓图发送）
- `e621.scale`：`day` / `week` / `month` / `year`
- `e621.date`：可选，不填用当前时间

### 性能与失败处理
- 单次取图约 **20 秒**（启动浏览器 + 加载列表页 + 详情页）
- 抓取失败时只回一句"这次没抽到能发的图，再试一次吧~"，**内部错误只进日志**
- 发送失败时回"图没取到，稍后再试试~"

### 验证结果
- 媒体类型过滤单测 **20/20 通过**（允许图片、排除全部视频格式）
- 抓取稳定性 **5/5 成功**，均拿到 `/data/download/` 原图直链
- 端到端：真实 gateway 收到 `#来点色图` → 抓图 → 发出**图片消息段**（`.png`，非视频）

## 十二、图片下载与代理（2026-11-12 修复）

### 问题

`#来点色图` 在 Suitman 的私聊里失败，gateway 日志：

```
图片发送失败 {"retcode": 200, "message": "read ECONNRESET"}
```

### 根因

- `e621.net` **主站**可访问（页面能抓）
- `static1.e621.net` **图片 CDN** 在本机不可达：curl 全部 HTTP 000，浏览器 72 张缩略图只加载成功 1 张
- NapCat 自己去下载图片 → `ECONNRESET`

**不是代码问题**：抓取、过滤、消息段格式都正常，堵点在图片下载。

### 修复

1. **gateway 自己下载图片，转 base64 再发送**
   - 走配置的代理（`config.qq.json` 的 `proxy.url`）
   - 用 `base64://<data>` 交给 NapCat，彻底绕开它的网络环境
   - 下载失败时自动退回 URL 直传（NapCat 偶尔能通）

2. 新增配置：

```json
{ "proxy": { "url": "http://127.0.0.1:7897" } }
```

留空表示直连。

### 验证结果

| 项 | 结果 |
|---|---|
| 代理下载原图 | ✅ 1.6MB PNG，2.4s |
| base64 转换 | ✅ 2.17MB 字符串 |
| **真实 NapCat 发送** | ✅ `status:ok, retcode:0, message_id=1243037188` |
| 端到端（假服务端） | ✅ 发出 base64 图片消息段 |
| 回归 | unit ALL PASS / skills 30 / commands 32 / e621 20 |

### 注意

- 代理端口变了要同步改 `config/qq.json` 的 `proxy.url`
- 图片限制 15MB（超过会跳过并回一句提示）
- 走代理后单次取图约 **22 秒**（抓取 20s + 下载 2s）

## 十三、图片记录与追问（2026-11-12）

### 需求
1. 发图时附带**原图链接**
2. 把图片和 **tag 记录到本地数据库**
3. 对方追问"这图里是什么"时，机器人能回答

### 实现

**1. 发图带链接**
图片与 `原图链接：https://e621.net/posts/<id>` 一起发出。

**2. 本地数据库**（`state/images.db`，SQLite）

| 字段 | 说明 |
|---|---|
| `ts` / `peerKey` | 发送时间 / 会话（`private:<uin>` 或 `group:<gid>`） |
| `postUrl` / `postId` | e621 原帖 |
| `imageUrl` / `ext` | 原图地址与格式 |
| `tags` | 该帖全部 tag（JSON 数组） |
| `artist` / `species` | 作者与物种相关 tag |
| `query` | 触发原文（如 `#来点色图`） |

使用 Node 内置 `node:sqlite`，**不引入第三方依赖**；运行时不支持时自动降级为 JSONL。

**3. 追问能力**
模型回复前，gateway 从数据库取**该会话最近 3 张图**，把原帖链接与全部 tag 注入提示词：

```
【你最近发给对方、且对方可能正在追问的图片】
- 发送时间：2026/11/12 18:40:58
  原帖：https://e621.net/posts/6851188
  全部标签：scripin, deer, mammal, anthro, ...
如果对方在问图里的内容，请根据上面的标签描述画面……
```

### 验证结果

| 项 | 结果 |
|---|---|
| 数据库单测 | **15/15 通过**（读写、会话隔离、持久化、上下文格式） |
| 端到端发图 | ✅ 文字链接 + 图片两段都发出，数据库写入 1 条 |
| **真实模型追问** | ✅ 模型回答："这图是一只鹿，兽人那种，戴眼镜还戴耳环，被捆起来了，穿着拘束衣，嘴里塞着口塞……" |
| 回归 | unit ALL PASS / skills 30 / commands 32 / e621 20 / image-context 15 |

### 说明
- tag 从详情页 `#tag-list` 抓取（同样走页面元素，不走 API）
- tag 抓取失败**不影响发图**，只是记录为空
- 追问只看**当前会话**，不会串到别人的图

## 十四、表情包收集与自我升级（2026-11-12）

## 十七、配置热重载（2026-11-12 修复）

### 问题
在人设里删掉「魔爪」相关内容后，机器人**仍然会提到魔爪**。

### 根因
`main.ts` 只在**启动时读一次配置**：
```ts
const { config } = loadConfig();   // 只读一次
```
之后全程用内存对象，运行时改配置**完全不生效**。

> 此前文档里写的"改完立即生效、无需重启"是**错误的**，现已修正。

### 修复
新增 `reloadConfigIfChanged()`，按文件 mtime 判断是否变更，在**每条消息处理前**调用：

```ts
async function handleEvent(ev) {
  reloadConfigIfChanged();   // ← 每条消息都检查
  ...
}
```

变更时打日志：`配置已热重载 {"personaName":"小助手","model":"harness"}`

### 验证
模拟「改动配置后不重启 gateway」，日志确认：
```
配置已热重载 {"personaName":"小助手","model":"echo"}
```

### 顺带修复
- **超大图送视觉模型报错**：>1.5MB 的图会 base64 过大，新增 `downscaleIfHuge()` 压到长边 1024。
- 表情包分析曾因旧进程未加载新模块而失败，重启后恢复正常。

### 注意
- 改**配置文件**：无需重启（热重载生效）
- 改**gateway 源码**：必须重启进程

## 十八、/reset 彻底重置（2026-11-12 修复）

### 问题
执行 `/reset` 后，历史聊天记录**没有真正清空**，机器人仍可能提到已删除的设定（如"魔爪"）。

### 根因（两个叠加）

**1. `/reset` 只清了内存**
```ts
clearHistory: (peerKey) => history.delete(peerKey)   // 只删内存数组
```
`chat.db` 的消息、`images.db` 的图片记录、学习画像**全都没动**。

**2. 更深层原因：gateway 不重读配置**
当时进程在 11:38 启动，配置在 11:39 修改。旧进程一直用**删除前的人设**，
所以即使 `/reset` 清了历史，模型仍按旧设定说话。

### 修复

**`/reset` 改为彻底重置**，覆盖四层：

| 层 | 处理 |
|---|---|
| 对话上下文（内存） | 删除 |
| 聊天记录（`chat.db`） | 按会话删除 |
| 图片记录（`images.db`） | 按会话删除 |
| 学习画像 | 重新生成 |

**只影响当前会话**，不波及其他人的数据。

### 现在的回复

```
已重置本会话：
  对话上下文：已清空
  聊天记录：清除 4 条
  图片记录：清除 1 条
  学习画像：已重建
```

### 验证
- 单测 **9/9 通过**（会话隔离、重复重置、计数正确）
- 端到端：真实 gateway 执行 `/reset` → 该会话消息数归 0
- 全量回归 9 套测试全通过

### 使用建议
改完人设后如果机器人还提旧内容：
1. 先确认配置已保存（设置页有提示）
2. 发 **`/reset`** 清干净当前会话
3. 还不行就重启 gateway（改源码必须重启）

## 二十二、重复取图修复：时间窗口内真随机（2026-11-13）

### 问题
配置了 `scale: "month"`（一个月热门），但机器人**反复发同一批图**。

日志证据：
```
12:29:29 取图成功 → post 6837874
12:31:37 取图成功 → post 6837874   ← 同一张
17:31:21 取图成功 → post 6837874   ← 又是同一张
```

### 根因

`buildPopularUrl` 里 `date` 一直取**当前时间**：

```ts
const date = opts.date ?? formatNow();   // ❌ 永远是"现在"
```

所以每次请求的都是**同一个时间窗口**（比如"截至现在的这一个月"），
里面的热门图是同一批，随机抽 20~50 张也会撞车。

### 修复：先在时间窗口内随机挑日期

```ts
const SCALE_DAYS = { day: 1, week: 7, month: 30, year: 365 };

export function randomDateForScale(scale: string): string {
  const days = SCALE_DAYS[scale] ?? 1;
  const backMs = Math.floor(Math.random() * days * 24 * 60 * 60 * 1000);
  return formatTime(new Date(Date.now() - backMs));   // ← 真随机
}
```

含义：`scale=month` 时，随机挑"一个月内某一天"作为窗口结束时间，
这样每次覆盖的是**不同月份区段**，图源范围大幅扩大。

### 附加优化：候选太少自动换日期

随机日期可能撞到冷清时段（整页只有 1 张图，甚至全是视频）：

```ts
fetchPopularImage(opts, minCandidates = 8, attempts = 3)
// 候选数 < 8 就换个随机日期再试，最多 3 次
// 冷清时段整页无图时也不会直接失败，会继续换日期
```

### 验证结果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| month 窗口 6 次取图 | 5/6 唯一（有重复） | **6/6 全部唯一** |
| day 窗口 8 次取图 | 7/8 唯一 | **8/8 全部唯一** |
| 候选数 | 6~56 波动大 | 9~37 稳定 |
| 耗时 | — | 2.2~6.0s |

### 配置说明
```json
{ "e621": { "scale": "month" } }
```
可选：`day` / `week` / `month` / `year`。窗口越大、随机范围越广、越不容易重复。

## 二十四、重复问题根治：已发送记录持久化（2026-11-13）

### 数据证据
统计最近 26 次图片发送：

### 修复：持久化到磁盘

```ts
// state/sent-posts.json 保存已发送的 postId 列表（最多 500 个）

function rememberSent(postId: string): void;           // 发送后写入并落盘
```

选图时：

```ts
const fresh = entries.filter(([id]) => !sentPostIds.includes(id));
if (fresh.length > 0) entries = fresh;
else sentPostIds.length = 0;   // 全都发过才允许重来
```

### 历史回填
首次启用时从 `state/outbox.jsonl` 回填了 **28 个**历史已发 postId，
避免升级后立刻重发旧图。

| 测试 | 结果 |
|---|---|
| 单元测试（加载/容错/截断/持久化） | **6/6 通过** |

### 说明
记录上限 500 个。一个月热门图总量通常几百张，达到上限后最早的记录会被挤出，

## 二十九、梗库世界书：文字问梗也能命中（2026-11-16）

### 问题（根因）

群里问「派大星跳伞是什么意思」，机器人答「跟派大星似的」——瞎猜。梗库里明明存着

`analyzeStickerNow()`（表情包视觉分析链路）。**纯文字消息的回复链路从来没查过梗库。**

### 方案：SillyTavern 世界书风格注入（新模块 `gateway/src/worldbook.ts`）

每轮回复前（reply.ts 的 harness 分支），扫描会话文本并把命中的梗注入为已知事实：

| 机制 | 说明 |
|---|---|
| 关键词触发（绿灯） | 当前消息 + 最近 `scanDepth`(默认3) 条同会话消息里出现条目 keywords |
| 向量兜底 | 关键词不足时用 crec `bge-m3`（1024维）算余弦相似度召回，阈值 0.55、topK 2 |
| 冷却 | 同会话同梗 `cooldownSec`(默认1800s) 内不重复注入；`constant:true` 蓝灯豁免 |
| 上限 | 单轮最多注入 `maxInject`(默认3) 条 |
| 噪音清洗 | `cleanMemeText()` 洗掉豆包采集残留（"微博哔哩哔哩/免费/下载电脑客户端"等） |
| 防编造 | 注入文本末尾写死「未列出的梗不要编造出处」 |

向量缓存落盘 `state/memes.vectors.json`（按条目文本 hash 增量重算），gateway 启动后台建库。

### 配置（`config/qq.json` 可选段，缺省用默认值）

```json
{
  "worldbook": {
    "enabled": true, "scanDepth": 3, "cooldownSec": 1800, "maxInject": 3,
    "vector": { "enabled": true, "threshold": 0.55, "topK": 2, "model": "bge-m3" }
  }
}
```

条目新增字段：`enabled:false` 停用（关键词与向量都跳过）；`constant:true` 每轮常驻注入。

### 顺带修复

- **reply engine 热重载失效**：`createReplyEngine(config)` 捕获的是构造时的 config 引用，
  `reloadConfigIfChanged()` 替换 config 对象后旧 engine 仍读旧值——人设/技能热重载
  实际一直没生效。现改为配置替换后重建 engine。
- `tests/memes.ts` 用例与「单字关键词不匹配」规则不同步（「逊」单字），已更新（15/15）。
